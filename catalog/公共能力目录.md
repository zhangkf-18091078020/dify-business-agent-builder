# 公共能力目录

平台统一维护。业务能力包**只声明依赖并绑定**，禁止业务内复制公共实现。  
监控等平台同事用**同一套** `dify-business-agent-builder` 搭建；交付物必须是新版 **Agents**，便于业务同事在顶栏 **Agents** 里直接找到并使用。

## 0. 权威位置（解决「写在自己本地别人拿不到」）

| 优先级 | 位置 | 谁用 |
|--------|------|------|
| **1（实况）** | **团队共用的 Dify**：已发布的公共 Tool / Skill / Agents（标签含 `公共`） | 任何人搭建时 **优先查这里** |
| **2（文档）** | **团队 Git 仓库里的本文件**（随 PR 提交，不是只改本机 `.cursor/skills`） | 给人看、给 AI 对照、登记 URL/状态 |
| 3（个人拷贝） | 同事电脑上的 Skill zip / `.cursor/skills/.../catalog/公共能力目录.md` | 仅缓存；**过期时以 1、2 为准** |

**监控同事搭完后必须：**

1. 在 Dify 打好标签并确认 Agents 列表可见；  
2. **更新仓库里的本文件**（工具名、Skill、Agent URL、状态=已上线）并 **推送到团队共享分支**；  
3. 不要只改自己解压的 zip 副本就结束——否则业务同事拉不到。

业务同事 / AI 绑定监控时：

1. 先在 Dify 按标签/名称检索是否已有监控公共资产；  
2. 再读仓库本文件核对；  
3. 本地 Skill 里目录与 Dify 不一致 → **以 Dify 已发布为准**，并提醒更新仓库目录。

| 项 | 说明 |
|----|------|
| 文档状态 | 现行（可扩展） |
| 仓库路径（本仓库） | `catalog/公共能力目录.md`（共享仓 `dify-business-agent-builder`） |
| 维护原则 | 新增公共能力：Dify 上线 → **提交本表** → 业务方可勾选 |
| 绑定方式 | 业务 Agent / Skill 引用已发布公共 Tool 与公共 Skill；亦可直接打开公共 Agent 对话 |

## 3. 如何认定「这是公共」（给人看 + 给 AI Skill 自动认）

后续业务 Agent 也是 **AI 用本 Skill 搭的**，不能靠人口头说「这是公共」。约定如下（**缺一不可到可检索**）：

### 3.1 强制标签（Dify，主识别信号）

| 资产 | 必须打的标签 |
|------|----------------|
| 公共 Agent / 公共 Workflow工具 / 公共 Skill | **`公共`**（固定字面，不要写成「公用」「公共能力」） |
| 同上 | **能力 ID 标签**：与本表「能力 ID」一致，如 `monitor` / `alert` / `schedule` / `asset-resolve` |
| 入口类（可选但推荐） | `〈能力ID〉-入口`，如 `monitor-入口` |
| 工具类（可选） | `〈能力ID〉-工具` |

AI 在共用 Dify 上判定「已上线公共监控」的方式：

1. 列出带标签 **`公共` + `monitor`** 的 Tool / Skill / Agents；  
2. 再对照本表「已上线」行；  
3. 一致则绑定，禁止重建。

### 3.2 命名约定（辅助）

| 类型 | 约定示例 |
|------|----------|
| Agent 显示名 | `监控Agent`（能力中文名 + Agent） |
| 业务 Skill | `monitor-ops`（`〈能力ID〉-ops`） |
| 工具名 | `list_monitor_*` / `query_monitor_*` 等，前缀能看出能力 ID |

### 3.3 本表登记（文档侧）

状态=`已上线`，并填齐 Tool 名、Skill 名、Agent URL。  
仅有标签、未改本表：AI 仍可以 Dify 标签为准绑定，但应提醒补登记。  
仅有本表、Dify 无标签：视为未就绪，停问，不要当公共绑定。

### 3.4 可见性

1. 必须新版 Agents（`/agents/…`）。  
2. 禁止只发工作室旧版。  
3. 业务同事 / AI 打开顶栏 Agents，靠标签 `公共` 也能筛到。

## 4. 变更规则

1. 变更已上线公共工具入参名：同步所有已声明依赖的业务 Skill，并在本目录备注。  
2. 下线：先确认无业务依赖，再改状态。  
3. 目录外新能力：先公共能力包 + 本表登记，再被业务引用。

## 5. 与生成契约的关系

- 包类型=公共 → 产出写入本目录，并必须有合格 Agents URL（若「独立 Agent=是」）。  
- 包类型=业务 → 只绑定本表「已上线」且勾选「是」的项。  
详见 [生成契约.md](../rules/生成契约.md)、[公共能力包模板.md](../templates/公共能力包模板.md)。
