> **给谁看**：人（同事、后续维护者）。

## 1. 这个仓库是什么

跨项目共享的 **Cursor / Claude Code / Codex Agent Skill**，用来在云澜 Dify 上搭建：

- **业务 Agent**（对象采集、应用采集…）
- **公共 Agent**（监控、告警、调度…；须打标签并登记目录）

它本身不是业务代码，也不是 Dify 控制台里已经上线的业务 Skill；后者是本包指导 AI **造出来** 的产物。


## 3. 规则优先级（改文件前先看）

```text
L3（单包「规则覆盖」） > L2（业务/公共分支，在 SKILL.md） > L1（rules/ + catalog）
碰 L0（rules/生成契约 硬底线）→ 拒绝覆盖并停问
```

- **全员约定**：改 `SKILL.md` / `rules/` / `catalog/`，推本仓。  
- **单业务特例**：改该业务自己的能力包「规则覆盖」表，**不要**为单业务改 `rules/01`～`04`。  
- **样板**：`examples/` 只示范怎么写能力包，不是线上真相源。

## 4. 出了问题改哪个文件

| 现象 | 改哪里 |
|------|--------|
| 工作流空壳 / 空参自测不过 | `rules/01-Workflow规范.md` |
| 发布为工具、命名、入参 | `rules/02-Tool规范.md` |
| 云澜 Skill 正文 / 路由 | `rules/03-Skill规范.md` |
| 搭成旧版 studio Agent | `rules/04-Agent规范.md`、`SKILL.md` |
| 总流程、环境优先、业务 vs 公共 | `SKILL.md` |
| 验收标准 / 禁止项 / L0 | `rules/生成契约.md` |
| 公共能力上线、URL、标签登记 | `catalog/公共能力目录.md` |
| 空模板字段不够用 | `templates/业务能力包模板.md` 或 `templates/公共能力包模板.md` |
| 样板写法过时 | `examples/…`（可选） |
| 安装方式、仓库 URL、其它 AI 挂载 | `docs/INSTALL.md` |
| 协作 FAQ、目录说明（本页） | `docs/使用说明.md` |
| Cursor 触发提示 | `cursor/project-rule-dify-agent-builder.mdc` |

改完流程：

1. 在本共享仓改文件 → commit → push。  
2. 若改了 L1 约定：更新 `SKILL.md` 里的 **规则版本** 日期。  
3. 各业务仓：`git submodule update --remote .cursor/skills/dify-business-agent-builder` → **新开对话**验证。

## 5. 怎么装、怎么用

完整步骤见同目录 **[INSTALL.md](./INSTALL.md)**（子模块 / 用户级 / Claude / Codex）。

摘要：

1. 业务仓挂子模块到 `.cursor/skills/dify-business-agent-builder/`。  
2. `git pull` + `git submodule update --init --recursive`。  
3. **新开** Agent 对话，说「按 dify-business-agent-builder 搭…」。  
4. 可选：复制 `cursor/project-rule-dify-agent-builder.mdc` 到业务仓 `.cursor/rules/`。

---

## 6. 公共能力怎么维护

1. 平台同事按本 Skill 搭公共 Agent（新版 `/agents/`）。  
2. Dify 打标签：`公共` + 能力 ID（如 `monitor`）。  
3. 回填并推送 `catalog/公共能力目录.md`（已上线 + URL）。  
4. 业务 Agent：**只绑定**已上线公共能力，禁止业务侧重做一套监控。

真相优先级：共用 Dify 实况 > 仓库 `catalog/` > 本机 Skill 拷贝。

---

## 7. 不要做的事

- 把 `docs/` 长文粘进 `SKILL.md`。  
- 每个业务仓手拷一份 `rules/` 导致规则分叉。  
- 只改本机 zip / 本地拷贝，不推共享仓，却指望同事自动生效。  
- 无 `公共` 标签就把某 Agent 当公共能力绑定。  
- 为单个业务去改全员 `rules/01`～`04`（应走 L3 能力包覆盖）。
