# dify-business-agent-builder · 使用说明

> 给人看。AI 执行入口是根目录 `SKILL.md`，不读本文件。  
> 全程在 **Cursor Agent 对话**里干活；改完 Skill 或能力包后请 **新开对话**。

跨项目共享的 Cursor Skill：指导 AI 在云澜 Dify 上搭 **业务 Agent**（对象采集、对象迁移…）和 **公共 Agent**（监控、告警…）。  
本仓不是业务代码；Dify 上的 Tool/Skill/Agent 是按本包造出来的产物。

远端：`https://github.com/zhangkf-18091078020/dify-business-agent-builder.git`

---

## 1. 操作流程（先看这个）

```text
① 让 Cursor 能读到本 Skill（本地 / 或 Clawbot 拉本仓到工作区）
② 新开 Agent 对话（工作区可以是本 Skill 仓，或业务仓）
③ 临时落盘能力包到工作区 dify-agent/（确认矩阵；非最终产物）
④ 再按能力包在 Dify 走 01～04 造物（最终产物）
```

发现顺序（详见 `SKILL.md`）：**Dify 取模块 → 页面探查 → 都扒不到则读 `dify-agent/` 技能包 → 模板回退**。环境/Dify 默认见 `SKILL.md`；允许探查后人确认。

### ① 安装 Skill

**A. 用户级（先试用，不改业务仓 Git）**

把本仓拷到（需存在 `SKILL.md`）：

```text
〈用户主目录〉/.cursor/skills/dify-business-agent-builder/SKILL.md
```

Windows 常见为 `%USERPROFILE%\.cursor\skills\...`；macOS/Linux 为 `~/.cursor/skills/...`。

PowerShell 示例（把 `〈本 Skill 仓本地路径〉` 换成你机器上的实际路径）：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.cursor\skills" | Out-Null
Copy-Item -Recurse -Force "〈本 Skill 仓本地路径〉" "$env:USERPROFILE\.cursor\skills\dify-business-agent-builder"
```

对 Cursor 说（若让它帮你拷）：

```text
把〈本 Skill 仓本地路径〉拷到
〈用户主目录〉/.cursor/skills/dify-business-agent-builder，
确保里面有 SKILL.md。不要改业务仓。
```

### ② 新开对话

1. 用 Cursor 打开工作区：可以是**本 Skill 仓**（远程/Clawbot 常见），或业务/公共仓。  
2. 新开一条 **Agent** 对话（旧对话不会自动加载刚装的 Skill）。  
3. 能力包临时落在**当前工作区根** `dify-agent/`（本仓已提供该目录）。  
4. 不必先「导入公共 Skill」；提到 `dify-business-agent-builder` 即可。

自检可以先说：

```text
你现在能读到 Skill dify-business-agent-builder 吗？
请确认 SKILL.md 路径，先不要搭任何 Dify 资产。
```

### ③ 先生成能力包（推荐，先不搭 Dify）

对 Cursor 说：

```text
按 dify-business-agent-builder：
1. 只生成工作区 dify-agent/〈业务名〉-业务能力包.md（临时；先不搭 Dify）
2. 禁止创建/修改 Dify 上新版 Agents 资产（可读已有 Chatflow 以反推）
3. 发现顺序：
   Dify 有对应模块 → 反推落盘，禁止浏览器再抓业务页；
   无模块 → 探环境页面汇总；
   Dify 与页面都扒不到 → 读工作区 dify-agent/ 已有技能包；
   仍无 → 模板回退并注明
4. 汇总给我确认后再定稿矩阵
5. 环境/Dify 不说则走 SKILL.md 默认（如「要搭建对象采集agent」）
```
期望目录：

```text
〈工作区根＝本 Skill 仓或业务仓〉/
└── dify-agent/
    └── 〈业务名〉-业务能力包.md
```

人审矩阵与待确认项；能力包写「暂缓 / §9 开放」的工具，下一步不要开建。  
模板：`templates/`；样子：[落盘示例/](./落盘示例/README.md)。

### ④ 确认后再搭 Agent

对 Cursor 说：

```text
按 dify-business-agent-builder，
读取本仓 dify-agent/〈业务名〉-业务能力包.md，
按包正式搭建：Workflow→Tool + Skill + 新版 Agents（/agents/）。
遵守包内造物红线与暂缓项：未关闭的开放项对应工具不要开建。
```

## 2. 两套东西别混

| 东西 | 放哪 | 作用 |
|------|------|------|
| 本 Skill（统一规范 L1） | 本仓 `rules/` + `SKILL.md` | 教 AI「怎么搭」（01～04） |
| 能力包（本业务规则 L3） | 工作区 `dify-agent/`（临时） | 告诉 AI「这个业务搭什么」；也可作扒不到时的回退源 |
| 最终产物 | 云澜 Dify | Workflow→Tool + Skill + `/agents/` |

规则优先级：`L3 能力包覆盖` > `L2 业务/公共分支` > `L1 rules/catalog`；碰 `L0` 硬底线一律拒绝。

---

## 3. 公共能力（监控等）

1. 平台同事用同一 Skill 搭公共 Agent（必须 `/agents/`）  
2. Dify 打标签：`公共` + 能力 ID（如 `monitor`）  
3. 回填并推送 `catalog/公共能力目录.md`  
4. 业务侧只绑定，不重建  

对 Cursor（平台侧）可以说：

```text
按 dify-business-agent-builder 搭「〈公共能力名，如 监控〉」公共 Agent，
必须新版 /agents/，标签含「公共」+「〈能力 ID，如 monitor〉」，
完成后更新并说明如何提交 catalog/公共能力目录.md。
```

真相：共用 Dify 实况 > 仓库 `catalog/` > 本机 Skill 拷贝。

## 4. 出了问题改哪

| 现象 | 改哪里 |
|------|--------|
| 工作流 / 空壳 | `rules/01-Workflow规范.md` |
| 发布为工具 | `rules/02-Tool规范.md` |
| Skill 路由 | `rules/03-Skill规范.md` |
| 旧版 Agent | `rules/04-Agent规范.md`、`SKILL.md` |
| 总流程 / 发现顺序（Dify→页面→`dify-agent/` 回退） | `SKILL.md` |
| 验收 / L0 | `rules/生成契约.md` |
| 公共上线登记 | `catalog/公共能力目录.md` |
| 安装方式 | [INSTALL.md](./INSTALL.md) |

改 L1 后：推本共享仓 → 更新 `SKILL.md` 规则版本日期 → 各仓更新子模块（或重拷用户级）→ **新开对话**。  
单业务特例只改该仓能力包「规则覆盖」，不要改 `rules/01`～`04`。

对 Cursor：

```text
不要改 rules/01～04。把本业务特例写进
dify-agent/〈业务名〉-业务能力包.md 的「规则覆盖」表。
```

---

## 5. 不要做

- 把本说明粘进 `SKILL.md`
- 每个业务仓手拷一份 `rules/` 导致分叉
- 只改本机拷贝不推仓库却指望同事生效
- 无 `公共` 标签当公共绑定；业务侧重做已上线公共能力
- 未确认矩阵就直接搭 Dify；能力包「暂缓」项强行开建
