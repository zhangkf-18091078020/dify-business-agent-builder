# 运行画像：在 Dify 上换模型 / 换环境

> 给人看。AI 搭 Agent 时也按本说明：`rules/01` §4、`rules/04` §4。  
> **生效位置：已搭好的 Dify。** 改本仓 Git 文件不会自动切换线上。

```text
一次运行 = 环境连接（Workflow 环境变量）× Agent 模型
```

---

## 1. 配置在哪

| 要换什么 | 在 Dify 哪里改 | 说明 |
|----------|----------------|------|
| **模型** | 顶栏 **Agents** → 某业务 Agent → 配置 → **模型** → **发布** | 每 Agent 一份；多业务可用 API 批量改 |
| **环境（API/默认资产）** | 工作室 → 对应 **Workflow 工具** → 编排 → 右上角 **环境变量** → 改值 → **发布为工具** | 变量名见下表；HTTP 用 `{{#env.名#}}` |
| **资产名→ID** | 公共 `resolve_asset` / `asset-resolve` | 按环境维护，业务不抄映射表 |

备忘（可选，不参与运行）：本目录可附 `profiles.yaml` 记录变量名与样板取值，**改它 ≠ 切换**。

---

## 2. 换模型（现在就能做）

1. 打开目标 Agent 配置页  
2. 改 provider / 模型名  
3. 建议：`think=false`，`temperature=0`，`max_tokens≥2048`  
4. 发布 → 跑能力包硬契约回归（确认保名 + 查状态不跑偏）  
5. 失败则在 Dify 改回原模型再发布  

平台默认模型约定后，十几个业务 Agent 可用 Console API 批量更新，避免纯手点。

---

## 3. 换环境 / 新环境搭建

### 3.1 同一 Dify 换业务库

1. 打开该业务各工具 Workflow（至少 create；理想 create/operate/list/stats 同名变量）  
2. 改环境变量（如 `OBJ_COLLECT_API_BASE`）  
3. 每个工具 **发布**  
4. 验收：鉴权、resolve、创建一条、查状态  

### 3.2 新环境从零搭

1. 在本环境 Dify 先写好各工具环境变量（或导入变量清单）  
2. 再按能力包造 Workflow→Tool + Skill + Agent（节点只引用变量，少写死 IP）  
3. 跑环境门禁 + 硬契约回归

## 4. 对象采集样板变量名

| 变量名 | 含义 | 样板值（222） |
|--------|------|----------------|
| `OBJ_COLLECT_API_BASE` | 业务 API 前缀 | `http://10.0.0.222:9996/esi_migration` |
| `OBJ_COLLECT_FOOTER_ENV` | 落款环境名 | `222` |
| `OBJ_COLLECT_DEFAULT_MAC_ID` | 默认主机 | `10328` |
| `OBJ_COLLECT_DEFAULT_DB_ID` | 默认数据源 | `11170` |
| `OBJ_COLLECT_DEFAULT_MAPPING` | mapping | `wangqds` |
| `OBJ_COLLECT_DEFAULT_TARGET_DB_TYPES` | 采集库类型 | `gaussdb(PG),gaussdb(M)` |
| `OBJ_COLLECT_DEFAULT_OBJ_TYPES` | 对象类型 | `TABLE,VIEW` |
| `OBJ_COLLECT_DEFAULT_RUN_MODE` | run_mode | `d,0` |
| `OBJ_COLLECT_DEFAULT_DESTROY_MODE` | destroy_mode | `keep` |

样板创建工具：工作室「对象采集创建任务工具」→ 环境变量（已示范）。  
token 放工具内默认或 Dify 密钥，**禁止**进 Git / Skill。

---

## 5. 与硬契约的关系

换模型/换环境 **不改** Skill 硬契约（保名、分轮、状态短路，见 `rules/03` §3）。  
契约与工具矩阵稳定；变的是「连哪套库」「用哪个模型」。
