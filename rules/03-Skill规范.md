# 03 Skill 规范（包内）

**改这里**：Dify **Skills** 里业务 Skill 怎么写、写什么。  
**不要写**：Workflow 节点细节、Agents 创建 API（见 01 / 04）。  
**同名**：已有同名业务 Skill → **先删再建**（见 `SKILL.md`）；新建内容必须满足本节，禁止再建「两字 description + 空正文」。

## 1. 一份业务一个 Skill

| 项 | 要求 |
|----|------|
| 机器名 `name` | `<biz>-ops`（如 `esi-compare-ops`） |
| 显示名 `display_name` | **必须中文**（如「数据比对操作手册」） |
| `description` | **必须完整**，见 §1.1；禁止只写业务两字 |
| 正文（SKILL.md / 指令区） | **必须非空**，含 §2 + §3；骨架见 `templates/业务Skill正文模板.md` |
| 挂载 | 挂到对应业务 Agent；公共能力另挂公共 Skill |

### 1.1 `description`（挂载列表用；硬门槛）

须用**一两句中文**同时覆盖：

1. 业务是什么；  
2. 能做什么（列表/创建/启停等，与矩阵「是」行一致）；  
3. 主工具名（英文蛇形，如 `list_esi_compare` / `create_esi_compare_task`）；  
4. 若有：公共依赖（如先 `resolve_asset`）、暂缓能力一句。

**合格示例**：

> 数据比对业务操作手册：查看比对任务列表、搭建/部署比对任务（部署后自动启动并查状态）；工具 `list_esi_compare`、`create_esi_compare_task`；话里出现主机/库名时先资产解析再调业务工具；独立启停/销毁现网暂缓。

**不合格（禁止交付）**：

- `数据比对` / `对象采集` / `ops` 等过短文案  
- description 有字但 **正文指令区空白**  
- 只列工具名、无路由/默认/安全约定  

落库前自检：`description` 建议 ≥40 个汉字或明显长于业务名本身；正文须含「工具列表」「路由」等标题或等价段落。

## 2. 正文最少章节（写入 Dify Skill 文件）

Builder **从能力包生成**完整正文（可先填 `templates/业务Skill正文模板.md`），再写入 Dify 并发布。禁止只建 Skill 壳。

1. **工具列表**：与能力矩阵「是」行一致（含 `list_*` 如有）；暂缓工具写明「未挂载/勿调」。  
2. **接口区分**（如有列表）：列表接口 vs 单条状态接口，避免混用。  
3. **默认参数**：用户未提时用能力包默认值（环境代号、默认主机/库表等；**不写** token/密码/完整内网 URL）。  
4. **路由**：用户说法 → 调哪个工具 / action。若依赖公共解析：仅当话里出现主机/数据源名时「先解析，**同一轮**再调业务工具；禁止只回解析结果」。未提资产名则直接业务工具 + 默认 id。  
5. **安全**：销毁等须确认（同句已明确除外）；矩阵暂缓的危险操作须明确告知用户暂不可用。  
6. **回复**：中文；先结论；优先工具原文；**禁止**输出长思考/自我配置分析。业务意图未完成前，禁止把「解析成功」或「配置已就绪」当作最终交付话术。  
7. **执行优先**：用户已给出业务意图（如「搭建对象迁移，采集任务：xxx」）→ Skill 须要求**立刻**调对应 Tool；禁止先验证 Agent/Skill/工具是否挂载。  
8. **创建半失败**：创建工具失败/超时/killed 后，须按流程名回查状态（或要求用户先查状态）；有记录 → 说清「未完成但已入库 + 失败步骤 + 状态」；无记录才说未落库。禁止凭超时断言无数据、禁止未确认就销毁。  
9. **销毁缺名**：未带流程名时**禁止**空参调销毁；本会话刚创建过 → 复述该名并请确认后再调；否则追问「销毁哪个流程名」。无销毁工具时写明暂缓。  
10. **错误码对用户友好（可选知识库）**：工具结果里出现业务 `code`（及 `msg`）时，可检索已绑定知识库中的错误码释义，用中文说明含义与建议动作；**查不到则保留原始 code/msg**。知识库只作释义补充，不得编造与工具结果矛盾的结论，也不得替代工具执行。

## 3. 写操作硬契约（搭业务 Agent 时通用，须写进 Skill）

与能力包验收对齐；改 Skill/Agent 后必跑回归（见能力包 A 组或等价用例）。

| ID | 契约 | 要求 |
|----|------|------|
| C1 | 确认保名 | 本会话已有流程名（用户原话或 preview「会话流程名」）后，「确认默认 / 可以创建 / 创建吧」**唯一动作**是调 `create(flow_name=该名)`；禁止纯文本编造「默认流程名：对象采集」；禁止 `test`/`my_flow`/`user_flow`/`对象采集`/`default`/空/静默自动名。本会话已有名时**禁止再问流程名**。占位名被工具拒绝 → **立刻**用会话真实名重试 create，禁止把拒绝转成「请用户再提供流程名」 |
| C2 | 分轮信息 | 第1轮齐：流程名+主机+数据源+业务关键类型参数（如采集的 `target_db_types`）；未齐只追问缺项。第2轮（若有 preview）确认范围后再 create；`preview` 必须带 `flow_name` |
| C3 | 状态短路 | 「查状态 / 这个流程 / 当前状态 / 状态怎么样 / 启动 / 停止」只用本会话流程名调 operate；**禁止**再问流程名；**禁止**重开搭建向导；**禁止**用 stats/preview 冒充查状态 |
| C4 | 销毁带名 | 同 §2「销毁缺名」 |
| C5 | 失败可读 | 超时/鉴权/缺参/后端错误 → 中文一句原因+可重试建议；禁止把思考过程 / `[ENDTHINKFLAG]` / shell 臆造当回复 |

业务特例（如「搭建=部署+启动+查状态」）写入正文路由，并在能力包「规则覆盖」有则照抄。

## 4. 生成方式（Builder）

1. 读能力包：矩阵「是」行、§默认、§危险、§验收、规则覆盖。  
2. 复制 `templates/业务Skill正文模板.md`，填业务名/工具名/路由/默认/暂缓。  
3. 写好 `description`（§1.1）与 `display_name`。  
4. 写入 Dify Skill 文件并 **发布版本**；再挂到 `/agents/` Agent。  
5. 自检：打开 Skill 页 → description 非两字壳、指令区可见完整章节；否则先删再建或补全后再交付。

## 5. 禁止写入 Skill

- 账号密码、token、完整内网 URL（环境用代号如「222」）。  
- 路由/示例里写「传入 token」或让 Agent 填写鉴权字段（鉴权见 `02` §2.1，工具内处理）。  
- 与工具矩阵矛盾的路由。  
- 把 Agent 短提示词该写的「角色一句」扩成整本手册（手册在 Skill，Agent 只短路由）。  
- Cursor/搭建元指令：如 verify configuration、investigative setup、先检查工具绑定、确认 Skill 是否配置等（那些是搭 Agent 的人看的，不是运行时业务 Skill）。  
- 后端改码、错误码表登记、Java 校验实现等**代码侧规范**（属人为改业务仓，不进本 Skill 包）。  
- **空壳 Skill**：仅有 name + 过短 description、正文空白却 publish。

## 6. 发布

编写后发布 Skill 版本；Agent 挂载的是已发布版本。改路由后须再发布并视情况更新 Agent 提示词短路由。
