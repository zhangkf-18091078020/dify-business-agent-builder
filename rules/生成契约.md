# 生成契约（包内验收单）

面向执行方 AI。造物细则见同目录 `01`～`04` 与根目录 `SKILL.md`；**本文件只定必须产出与验收**。

## 执行身份（L0；与 `SKILL.md` 同义，不可用 L3 覆盖）

你是 **Builder（Dify 搭建造物者）**，不是业务系统操作员，也不是已上线业务 Agent。

| 本次要交付 | 本次不要做 |
|------------|------------|
| Dify：**Workflow→Tool + Skill + 新版 Agents（`/agents/` + 已挂 Skill）** + 执行报告 | 去业务环境创建/启动真实业务流程或任务，并当作「搭好了 Agent」 |
| 能力包矩阵里的「创建/搭建」→ **实现对应 `create_*` 等工具并挂到 Agent** | 把用户「要能创建业务流程」理解成 **现在**去业务页执行创建 |
| 将 `04` §2.0 / §2.1 写进**产物** Agent/Skill | Builder 自己按业务意图句去调业务接口（除非人明确授权工具自测） |

**完成定义**：无 `/agents/` URL 或未挂 Skill = 不合格；仅有工作室 Workflow / 仅有业务环境真实任务 = 不合格。

目标：按**业务能力包**或**公共能力包**（已确认矩阵）在 Dify 产出 **Workflow→Tool + Skill + 新版 Agents**。  
- 业务：给该业务用，可绑定已上线公共能力。  
- 公共（监控等）：给全团队用；Agents 顶栏可见；并回填 `catalog/公共能力目录.md`。  
无包时发现顺序见 `SKILL.md`：**Dify 模块 → 环境页面 → 仍扒不到则读工作区 `dify-agent/` → 再否则模板回退**。能力包为临时中间产物，最终产物在 Dify。

## 1. 必读（本 Skill 包内）

1. `SKILL.md`（流程；发现顺序含 `dify-agent/` 回退）  
2. `rules/01-Workflow规范.md` / `02-Tool规范.md` / `03-Skill规范.md` / `04-Agent规范.md`  
3. `catalog/公共能力目录.md`  
4. **本业务**能力包（工作区 `dify-agent/`）；无则先走 SKILL「发现顺序」再临时落盘；空模板见 `templates/`  

（**以本 Skill 包为准**。）

## 2. 必须产出（Dify）

| # | 资产 | 规范 |
|---|------|------|
| 1 | 业务 Workflow→Tool（1～N） | `01` + `02`；与矩阵一一对应 |
| 2 | Skill（1） | `03`（业务或公共） |
| 3 | Agent（1） | `04`（必须 `/agents/` + Skill 挂载；公共也必须，便于同事看见） |
| 4 | 标签 | 业务标签；公共另加 `公共`、能力名 |
| 5 | 执行报告 | 含 Agent URL、自测、待确认；**公共须含目录已更新** |

禁止只交 Markdown 冒充交付。

## 3. 公共依赖（业务侧复用）

按能力包「依赖公共能力」表绑定：

- 目录中状态为 **已上线** 且勾选「是」→ **只绑定**已有公共 Tool/Skill，挂到本业务 Agent；业务 Skill 写路由。  
- 用户说「要用监控」但目录未上线 → **停问**，禁止在业务流里重做一套监控。  
- 目录无该 ID → 停问，先补公共能力包 + 目录，再绑。  
- 公共已有独立 Agent URL 时：执行报告中附上，供业务同事直达；**不要**再复制一个监控 Agent。

## 4. 执行摘要

1. 有包则校验；无包则按 `SKILL.md`：**Dify 模块 → 环境页面 → 二者都扒不到业务流程则读 `dify-agent/` 技能包 → 仍无才模板回退**；人确认后开建。  
2. 未确认矩阵前禁止开建新版 Agents 资产。  
3. 按 `01`→`02`→`03`→`04` 实现；列表默认候选见 `01` §2.4。  
4. 发布失败 → 列人工步骤，停止破坏性重试。

## 5. L0 硬底线（能力包「规则覆盖」不得覆盖；撞到则停问）

1. 必须新版 Agents（`/agents/` + Skill 挂载）；禁止交付旧版 AGENT。  
2. 禁止无证据空壳工具；禁止编造 URL/字段/成功码/密钥。  
3. 禁止无包时跳过「Dify 模块反推 / 环境探查 / `dify-agent/` 回退」直接按模板编造能力（除非均不可用并注明模板回退）。**Dify 已有对应 Chatflow/模块时，禁止再用浏览器访问业务页抓接口来写能力包。** Dify 与页面都扒不到时，**禁止跳过**当前项目 `dify-agent/` 不读就模板空想。  
4. 禁止公共不建 Agents；禁止公共已交付不回填**仓库**目录并不推送。  
5. 禁止业务侧重做已上线公共能力；禁止无强制标签（`公共`+能力 ID）却当公共自动绑定。  
6. 禁止 Skill 写密码/token/完整内网 URL；禁止 Agent 提示词塞整本手册。  
7. **身份**：执行方是 Builder；禁止把「搭业务 Agent」做成「去业务环境搭建真实业务流程/任务」；禁止只交 Workflow、不交 `/agents/` + Skill 挂载却宣称完成。  
8. **`04` §2.0 受众**：该节约束**产物**业务 Agent 的运行时路由；禁止 Builder 误读后代替用户执行业务创建（自测须人明确授权）。

## 5.1 其它禁止

1. 业务流内复制公共映射。  
2. **同名约定冲突时未按 L3>L2>L1 合并，或用 L3 覆盖 L0。**  
3. 创建类工具失败/超时后不回查却断言「未入库」，或未确认静默销毁残留。  
4. 销毁/删除空业务主键直调（缺名须追问或确认本会话刚创建的任务）。  
5. 把后端改码、错误码表、Java 实现写进本 Skill 包当作搭 Agent 规范（代码侧由人处理）。

## 6. 停问

- 能力清单未确认；无 Chatflow/模块且环境看不清、`dify-agent/` 也无对应包、用户未确认模板回退。  
- 已选能力无入口；接口字段冲突/未知；硬约束未确认。  
- 鉴权/成功码不明；公共能力未登记；无 Dify 权限。  
- 声称「从 Chatflow 反推」但模块内看不清接口却仍编造字段。

## 7. 验收勾选

- [ ] 矩阵仅含已确认项；来源为 **Dify 模块反推** / 环境探查 / **`dify-agent/` 回退** /（注明的）模板回退  

- [ ] 无空壳；列表与单状态未混用  
- [ ] Tool 均可工作室调试；公共依赖仅绑定「是」  
- [ ] 执行身份未串戏：未用业务环境真实任务冒充搭好 Agent；交付含 `/agents/` + Skill  
- [ ] Agent 为 `/agents/` + 已挂 Skill；提示词短路由（含 `04` §2.0 业务意图优先 + §2.1 解析串联）  
- [ ] （仅当人授权自测时）业务意图句（如「搭建…采集任务：名」）轨迹含对应业务 Tool，无「只分析不调工具」  

- [ ] 绑了公共解析时：自测「资产名+搭建/列表」轨迹为解析→业务 Tool  
- [ ] 业务仓 `dify-agent/` 仅 `README.md` + 能力包 md（见 `04` §5）  
- [ ] 危险操作有确认约定；销毁缺名有追问/确认约定；用例已跑或标明阻塞  
- [ ] 创建类：失败/半失败路径有回查约定（是否入库 + 失败步骤）；自测或标明阻塞  
- [ ] （可选）错误码知识库：仅释义，不替代工具 `code`/`msg`  
- [ ] 执行报告已交（含 **规则版本**、本包 **规则覆盖项 ID** 列表；无覆盖写「无」；报告不落盘到 `dify-agent/`）  
- [ ] 未用 L3 覆盖任何 L0
